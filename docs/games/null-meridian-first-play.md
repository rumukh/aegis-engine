# NULL MERIDIAN: first-play protocol

Use a fresh, playable evaluation build for each participant. **No first-time human result has been recorded here.** The scripted win is a regression fixture, not a pacing measurement. The 8–12 minute design target is for comparison after observation, not a deadline or an instruction to the player.

## Before inviting a player

The facilitator records the build's full Git revision, URL or artifact identifier, browser, input device, viewport, quality and whether sound is on. Verify that an ordinary play page opens from the beginning and the controls are available. Use a fresh run, without a replay, debug overlays, demo input or saved progress. For a checkout: `npm ci`, `npm run build`, `npm run play`; open **NULL MERIDIAN** from the local collection. Do not share route files, this project's walkthroughs, timings, benchmark results or developer footage.

Recruit a person who has neither worked on this game nor seen its route. Participation is voluntary; tell them it is an atmospheric horror game and they may pause, mute or stop at any point. No names, contact details, account identifiers, audio, video or screen recording are needed.

## Read only this to the participant

> Please play this game as you normally would. You can use the game's own menus and controls. I'm testing the game, not you; there is no score for speed. If you want help or want to stop, say so. I'll take anonymous notes.

Start the elapsed-time clock when a ready player takes control, **not** while assets are loading. Do not point, explain an objective, steer the character or demonstrate a control. If the player requests assistance, note the elapsed time and their words; ask whether they want to continue independently or end the uncoached portion. Stop the primary measurement at first completion, abandonment or first coaching. Note pauses and restarts rather than resetting the clock. Keep post-coaching activity out of the uncoached result.

## Observation record — one per real session

| Field                                                                          | Record |
| ------------------------------------------------------------------------------ | ------ |
| Build revision / artifact; date                                                |        |
| First time / no route knowledge confirmed                                      |        |
| Input device, browser, viewport, quality, sound                                |        |
| Start, end, total elapsed time, time paused                                    |        |
| Outcome: completion / abandonment / coaching requested and supplied            |        |
| Restarts: count, times, stated reason if offered                               |        |
| Help requests: time, request, facilitator response                             |        |
| Confusion: elapsed time, visible cue, observable action or participant's words |        |

After stopping, ask “What did you think you were trying to do?” and “Was there a point where you couldn't tell what to do next?” Record answers without adding an interpretation. Separate **observations** (e.g. returning to the same doorway three times) from **recommendations** (e.g. testing a clearer label). Report even non-completion; never substitute a second, coached attempt, a browser agent, an internal rehearsal or this blank form. A single observation is not a population estimate.
